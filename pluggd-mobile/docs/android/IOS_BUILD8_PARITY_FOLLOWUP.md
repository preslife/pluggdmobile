# Android follow-up after iOS Build 8

This is our private checklist for the Android pass after iOS Build 8 has been submitted. It is not an instruction to change or release Android during the current iOS phase.

## What iOS Build 8 adds beyond Build 7

- Homepage completion: Featured Track retained, What's Moving Now added in the accepted order, complete editorial/opportunity/Soundboard/event rails, corrected artwork and live admin-curation wiring, real destinations and player progress.
- Discovery completion: seasonal-feature lifecycle, complete visual destination navigation, Start Somewhere Unexpected/admin curation, canonical creator attribution, Community Pulse and polished linked destinations for Releases, Mixes, THE PLUG, BeatPlug, Soundboards, Opportunities, Creators and Store.
- Community media parity: full image/video viewing inside threads, contain/zoom/paging/native video controls, complete reply cards and real creator names/handles instead of generic user labels.
- Creator Profiles: creator-controlled accent/configuration, circular identity treatment, complete hero actions, Creator Pick, searchable multi-format catalogue/player, Membership/Support, Community, Videos, Store/beat licensing, Connect Card, owner management routes, tabs, safe external links, haptics and accessibility polish.
- Events: normal Events preserved as default; lifecycle-controlled Carnival takeover; canonical search/time/category/group filtering, Browse/Map parity, ticket/detail links, compact list/Local Scene/Event Board hierarchy, artwork/date corrections and immediate Map return with state preservation.
- Creator Studio: corrected navigation drawer and route scroll state; truthful signed-out/preview boundaries; premium Home/Apps/Create/More/My PLUGGD, Connect Card, catalogue, video, Soundboard, commerce, financials, splits and embedded-browser surfaces; guarded validation and complete route coverage.
- Release workflow: web-equivalent Release-only AI declaration, conditional generated-element/audio/identity/rights/no-impersonation fields, exact versioned `distribution_settings.ai_disclosure`, local draft recovery and Review/final-review truth. Beat and Mix behaviour remains unchanged.
- Shared product completion: Carnival Hub, Listening Floor/Releases, BeatPlug, Mixes, THE PLUG, Opportunities, Soundboards, Store, legal readers, global player/navigation, creator identity/data completeness and resilient loading/error/access states.

## Android pass required later

- Start from the exact submitted iOS Build 8 source commit; inventory which changes are already shared React Native code and which require Android-specific layout, permission, media, map, billing or lifecycle handling.
- Re-run the complete source/type/contract suite and add focused Android assertions only for real platform differences.
- Perform compact and large Android visual comparisons for every section above; no plain-stack fallback, clipped artwork, hidden tab, duplicated date or dock/player obstruction.
- Verify real Android hardware cold launch, killed-process recovery, background audio, progress/seek, notification tap routing, media viewer/video controls, deep links, back handling, keyboard/safe-area behaviour and accessibility.
- Revalidate Mapbox/events, ticket browser handoff, file/media pickers, Creator upload private-draft flow, Studio authentication and Android purchase policy without making public content or real purchase mutations.
- Recheck Play Billing/library deadlines, target SDK, privacy/data-safety declarations, content rights, screenshots, release notes, signing and version code before any Play build or rollout.
- Treat the current shipped Android release as the rollback baseline. Do not submit until the parity matrix is visually and functionally accepted on hardware.
