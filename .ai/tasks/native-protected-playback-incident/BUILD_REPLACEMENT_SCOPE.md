# Replacement iPhone build scope (29 September 2026)

Baseline: native `origin/main` at `ce2e1f6f` is the clean Build 13 source. The installed/App Store Connect candidate is `1.0.0 (13)`. The original native checkout contains unrelated dirty work and is not a build source. A replacement requires a new build number, exact source commit, physical install and a fresh App Review evidence check; upload and submission remain separate gates.

| Change since Build 13 | Native impact | Replacement action |
| --- | --- | --- |
| Web/backend BeatPlug protected previews (#172) | **Required.** Published Beats now expose retained relative preview paths; Build 13 rejects them. | Resolve by Beat ID through the live signer; never play or expose the paid master as fallback. |
| Public Mix storage, including Channel One | **Required.** Channel One's public-shaped URL points to the private `audio-files` bucket. | Resolve by Mix ID through the live signer. Test Channel One on device. |
| Expiring private release links | **Required compatibility.** Some release tracks/previews carry old signed `audio-files` URLs. | Refresh those by track/release ID; keep existing public CDN/release-audio behavior. |
| Long Mix and queue lifetime | **Required backend companion.** Current public signed links last five minutes. | Release the separately reviewed public-stream four-hour signer change; keep owner-only paths at five minutes. Test a long Mix/queue. |
| Slow Still ah Link / Glass Moon starts | **Device acceptance gate.** Both are ~45 MB public WAVs; their origin supports fast byte-range responses. | Try bounded iOS forward buffer in source, then time tap-to-sound on the actual phone. Do not claim fixed from source or desktop results. |
| MP3 export/processing UI | **No automatic release derivative.** `AudioProcessor` simulates conversion; `process-audio-upload` calculates duration/waveform; `MP3Encoder` is used by export tooling. Neither live release is linked to an `audio_files` streaming copy, and neither creator's release-audio folder has an MP3/M4A copy. | If the physical WAV start still stalls, make a separate reviewed streaming-derivative/storage/selection change while preserving lossless masters and download rights. Do not swap master URLs to MP3. |
| Web Mixes, album, Releases and BeatPlug presentation fixes (#175, #179, #180, #183, #187) | Web implementations do not enter the native binary. Build 13 already has its own Listening Room, multi-track list and BeatPlug controls. | Preserve native UI and test Mix transport/seek, album continuity and Beat audition in the new candidate. No blind web code port. |
| Web creator communities, fan checkout and purchase/download repairs (#190, #195, #196, #200) | Shared backend behavior and App Review flows may have changed; no native source replacement is established by these web PRs. | Recheck Community report/delete, creator membership, restore/purchases and release download with review accounts on the new phone. Fix a demonstrated incompatibility before archive. Do not bundle untested optional web features. |
| Live reminders, public polish, Carnival expiry and other web-only releases | No direct binary dependency found. Native Carnival Home promotion already checks campaign dates. | Retain Build 13 native behavior; smoke Home, Live and creator routes during device acceptance. |

Blocking sequence: review/merge/deploy public signer; review native fix; explicit native-main integration gate; create a new local iPhone build number; install and time playback; run App Review route and StoreKit smokes; then separately decide archive/upload and App Store Connect replacement. Preserve Build 13 and its materials until the new candidate passes.
